## Constitutional definition

> **Institutional learning is the evidence-governed succession of digital implementations beneath a durable capability, preserving semantics and authority while reducing the cognition required to perform a work class.**

```text
CAPABILITY                         durable institutional promise
CAPABILITY REVISION                exact semantics, authority, work class, evidence
CAPABILITY OCCUPANCY               current implementation strategy
IMPLEMENTATION                     replaceable performer
SUBSTRATE                          inference | configuration | fixed
```

A substrate transition is not a capability revision. If semantics, authority, work-class scope, or evidence obligations change, the operation is rejected as sedimentation and must enter the ordinary revision/promotion path.

## Digital substrates

```text
INFERENCE
  model inference reconstructs meaning on each execution

CONFIGURATION
  reprogrammable digital structure performs stable portions
  residual uncertainty routes to an admitted fallback

FIXED
  deterministic digital artifact performs its admitted domain
  changes require a new artifact revision
```

The names borrow the CPU/FPGA/ASIC analogy from Canon §9.4. No physical hardware is required or implied.

## Permanent flow

```text
Heartime
  ↓ reference-only wake
Sedimentation Reconciler
  ↓ reads current scope and occupancy from Registry
Evidence
  ↓ returns measured work-class profile
  ├─ insufficient evidence      → abstain
  ├─ stable, no candidate       → Imagineering construction responsibility
  ├─ candidate not verified     → independent evaluation responsibility
  ├─ verified and economical    → Process transition proposal
  └─ hardened and contradicted  → Process softening proposal
```

The controller never activates an implementation. Promotion and occupancy change remain Process/Registry responsibilities.

## Evidence requirements

A hardening proposal requires all of the following:

- a current profile for the exact occupancy and implementation;
- a minimum evidence window and run count declared by policy;
- bounded exceptions, contradictions, uncertainty, and quality regression;
- an exact candidate for the next admitted substrate;
- preserved semantic, authority, work-class and evidence contracts;
- an equivalence assessment by an actor other than the candidate author;
- independently observed cost, quality, latency and cognition fraction that satisfy the capability policy;
- an exact fallback implementation reference, revision and substrate;
- a transition proposal naming the exact source occupancy and target implementation strategy.

Counts and rates are derived. `exception_rate` must equal `exception_count / observed_runs`; quality regression is derived from observed quality against the profile baseline; narration and candidate forecasts are not evidence.

## Softening

A non-inference occupancy must retain an inference-capable fallback. Contradiction, drift, workaround, degradation, exception pressure, or uncertainty pressure may cause the reconciler to ensure a softening proposal.

Softening is not failure recovery by accident. It is an attributable institutional transition back toward a more plastic substrate.

## Independent state dimensions

Capability revision, candidate lifecycle, occupancy status, substrate and epistemic state are independent. A verified candidate is not active; only Process promotion and Registry occupancy make it active. An active occupancy may be degraded without changing capability semantics.

## Idempotency

The protocol separates the durable institutional obligation from the evidence observation that found it:

```text
obligation key
  contract + learning scope + capability revision
  + learning-policy identity/revision + current occupancy
  + decision + target substrate + candidate revision where applicable

decision-evidence key
  obligation key + exact work profile + exact assessment where applicable
```

A new profile can create new attributable decision evidence while reusing the same open construction, evaluation or transition obligation. A policy revision creates a new obligation. A controller may evaporate and run again without duplicating institutional consequence.
