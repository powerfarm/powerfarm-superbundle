## How to read this

Document 1 declares that competence should move between digital substrates and
that stable competence repeatedly purchased as frontier inference is unfinished
construction. This document defines the protocol that makes that claim
executable.

The protocol is permanent. Its current provider settings and organ bindings are
replaceable. Local verification is not deployment evidence.

---

## 1. Purpose

PowerFarm learns when experience changes the durable structure through which a
capability is performed.

> **Institutional learning is the evidence-governed succession of digital
> implementations beneath a durable capability.**

The purpose is not merely to reduce model cost. The purpose is to preserve
competence so that settled work no longer has to be reconstructed by cognition,
while retaining an explicit route back to a more plastic implementation when
reality changes.

---

## 2. Capability endures; implementation occupies

```text
CAPABILITY                 durable institutional promise
CAPABILITY REVISION        exact semantics, authority, work class and evidence
CAPABILITY OCCUPANCY       current implementation strategy
IMPLEMENTATION             replaceable performer
SUBSTRATE                  inference | configuration | fixed
```

> **Capability identity MUST survive substrate succession.**

A substrate transition MUST NOT change:

```text
semantic contract
work-class scope
authority contract
evidence contract
```

If any of these change, the operation is a capability revision. It is not
sedimentation and MUST enter the ordinary construction and promotion path.

One capability revision has exactly one active occupancy for a work class. A
candidate, shadow implementation, or open transition proposal is not an active
occupancy.

---

## 3. The substrates are digital

```text
INFERENCE
  meaning is reconstructed by model inference on each execution

CONFIGURATION
  reprogrammable digital structure performs stable portions
  residual uncertainty routes to an admitted inference fallback

FIXED
  deterministic digital artifact performs its admitted domain
  semantic change requires a new artifact or capability revision
```

The CPU, FPGA and ASIC language in Document 1 is an analogy for flexibility,
reconfiguration and rigidity. This protocol requires no physical programmable
hardware.

> **A capability SHOULD occupy the cheapest digital substrate that still permits
> the change it actually undergoes.**

“Cheapest” is evaluated under declared quality, latency, uncertainty, attention
and consequence constraints. It does not mean lowest nominal provider price.

## 4. Independent state machines

Capability learning does not have one linear lifecycle. Four independent
questions MUST remain separate.

```text
CAPABILITY REVISION     what does the capability promise?
IMPLEMENTATION          is this performer admissible?
OCCUPANCY               what currently performs the capability?
SUBSTRATE               how much cognition is reconstructed at runtime?
```

### 4.1 Capability revision

```text
DRAFT → ADMITTED → SUPERSEDED
                  ↘ WITHDRAWN
```

A capability revision changes only when semantics, work-class scope, authority,
or evidence obligations change. Substrate succession MUST NOT create a new
capability revision.

### 4.2 Implementation candidate

```text
DRAFT → CANDIDATE → SHADOW → VERIFIED
   └──────────────→ REJECTED
                    INVALIDATED
```

These states concern one exact implementation revision. `VERIFIED` means the
independent assessment satisfies its evidence contract. It does not mean the
implementation is active. Only Process promotion and Registry occupancy can
make it active.

A contradicted assessment invalidates the current candidate path and creates a
construction obligation for a successor. A non-final assessment continues the
evaluation obligation; it does not silently count as failure or success.

### 4.3 Occupancy

```text
ACTIVE ↔ DEGRADED
```

Occupancy is the current performer under a capability revision. `DEGRADED` may
trigger immediate operational fallback and a softening proposal, but neither is
a capability revision.

### 4.4 Substrate

```text
INFERENCE → CONFIGURATION → FIXED
```

Hardening proceeds exactly one admitted rung at a time. Version 1 softening
returns to the exact admitted inference fallback. The policy's substrate list
MUST be a contiguous prefix of this order; it cannot skip, reorder, or invent a
rung.

The state machines may move independently. A verified candidate may wait for
promotion. An active configured occupancy may become degraded. A capability
revision may be superseded while historical implementations and evidence remain
resolvable.

## 5. Work-class evidence

A capability is never declared “learned” in general. Evidence is accumulated for
an exact pairing:

```text
CapabilityRef
+ capability revision
+ WorkClassRef
+ current CapabilityOccupancyRef
+ current ImplementationRef
+ distribution identity
```

A work profile MUST contain measured, attributable values for at least:

```text
window
observed runs
stable runs
exceptions
contradictions
workarounds
residual uncertainty
quality
cost per run
latency
input-distribution identity
evidence references
```

Counts and rates MUST be derived. A future-dated profile, a profile for a
superseded occupancy, or a profile without evidence references MUST NOT drive a
transition.

Repeated execution alone is insufficient. Stable repetition with unresolved
workarounds or changing distributions is not settlement.

## 6. Hardening

Heartime makes forgetting impossible. It periodically asks whether the current
substrate is still justified.

```text
stable + expensive + sufficiently evidenced
                 ↓
       construction responsibility
                 ↓
          provisional candidate
                 ↓
          independent shadow run
                 ↓
          transition proposal
```

A hardening proposal requires:

1. the current profile satisfies the scope's explicit stability thresholds;
2. a candidate exists for the next admitted substrate;
3. candidate semantics, authority, work class and evidence obligations equal
   the current capability revision;
4. the candidate names an exact artifact and exact inference fallback lineage;
5. an evaluator other than the candidate author supplies equivalence evidence;
6. observed candidate quality, cost, latency, uncertainty and cognition fraction
   satisfy the declared policy;
7. Process can reconstruct the exact source occupancy and target implementation
   strategy.

Candidate forecasts are construction metadata. They are not admission evidence.
Promotion economics MUST use independently observed values.

---

## 7. Partial sedimentation

Sedimentation is not binary.

```text
before
  inference performs retrieval, classification, calculation,
  policy application and ambiguity adjudication

after
  digital structure performs the stable portions
  inference receives only residual uncertainty
```

Every occupancy records a `cognition_fraction`. Every candidate and independent
assessment records the expected and observed fraction respectively.

> **The protocol asks which portion no longer requires cognition.**

A candidate that changes provider price without reducing the admitted cognition
fraction may be an implementation succession inside a substrate. It is not, by
that fact alone, sedimentation.

Residual uncertainty MUST remain visible and MUST route to the admitted fallback
or to abstention. It may never be hidden inside a deterministic success claim.

---

## 8. Independent evidence

The candidate author MUST NOT certify candidate equivalence.

The independent assessment MUST report observed values, including:

```text
runs
exceptions
contradictions
quality
cost
latency
residual uncertainty
cognition fraction
evidence references
```

Quality regression is derived from observed quality and the declared baseline.
Savings are derived from observed cost. Latency and cognition reduction are
measured, not narrated.

A compilation success, candidate README, model-written summary or candidate
forecast is not equivalence evidence.

---

## 9. Softening

Learning includes the return of plasticity.

A non-inference occupancy MUST retain an exact inference fallback. The following
conditions may produce a softening proposal:

```text
contradiction
degraded occupancy
exception pressure
workaround pressure
residual-uncertainty pressure
```

Softening is an ordinary attributable institutional transition. It does not
rewrite history or erase the hardened artifact. The prior occupancy remains in
lineage, and the evidence explaining the return to inference remains resolvable.

> **Hardening without softening is fossilization, not learning.**

## 10. Institutional ownership

```text
HEARTIME
  owns the obligation to look again

REGISTRY
  owns capability identity, revisions, implementations, occupancy and fallback

EVIDENCE
  owns work profiles, independent assessments and decision evidence

IMAGINEERING
  owns provisional construction and evaluation responsibilities

PROCESS
  owns transition proposals, authority gates and promotion

SEDIMENTATION RECONCILER
  owns no institutional state; reads, derives and ensures idempotent obligations
```

The reconciler MUST NOT expose an activation or promotion method. It MUST NOT
write Registry occupancy directly.

## 11. Level-triggered and idempotent

Every pass reads current organ-owned state. No event, queue offset or prior
controller memory is required to discover the obligation again.

The protocol uses two semantic identities because an institutional obligation
and the evidence that caused one observation of it are not the same thing.

```text
OBLIGATION KEY
  contract
  + learning scope
  + capability revision
  + learning-policy identity and revision
  + current occupancy
  + decision
  + target substrate
  + candidate identity and revision, where applicable

DECISION-EVIDENCE KEY
  obligation key
  + exact work-profile revision
  + exact assessment revision, where applicable
```

A new evidence window may produce a new attributable decision record while
resolving to the same open construction, evaluation, or transition obligation.
A change of learning-policy revision creates a new obligation because the law
under which the decision is made has changed.

A controller may die after creating any one of these objects. The next pass MUST
recover from durable organ state and MUST NOT duplicate institutional
consequence.

---

## 12. Heartime boundary

Heartime sends only:

```text
BeatRef
ReconcilerRef
reason
CapabilityLearningScopeRef
```

It receives a compact reference-only summary. Capability, implementation,
profile, candidate, policy, assessment and proposal bodies MUST NOT enter
Heartime state.

The Heartime setting selects a reconciler by canonical `ReconcilerRef`. A new
seam does not create a new scheduler.

## 13. Negative controls

| ID | Property | Refuted by |
|---|---|---|
| L1 | Identity survives succession | A substrate change creates a different CapabilityRef or capability revision |
| L2 | Meaning is preserved | Candidate semantic, authority, work-class or evidence contract differs |
| L3 | Evidence is independent | Candidate author is accepted as equivalence evaluator |
| L4 | Economics are observed | Promotion uses candidate forecasts instead of measured assessment values |
| L5 | Cognition actually falls | A candidate is promoted without the required observed cognition reduction |
| L6 | Profiles are current | Future or superseded-occupancy evidence drives succession |
| L7 | Hardening is bounded | A candidate or proposal skips an admitted substrate rung |
| L8 | Softening exists | A contradicted hardened occupancy produces no softening proposal |
| L9 | Fallback is exact | A non-inference occupancy cannot name revision and substrate of its fallback |
| L10 | Promotion is external | The reconciler activates or writes occupancy directly |
| L11 | Duplicate passes are harmless | Re-running the same obligation creates duplicate institutional consequence |
| L12 | Partial learning is visible | Residual inference is hidden or omitted from occupancy |
| L13 | Description is not evidence | Typed quality, cost or latency claims are accepted without observed evidence |
| L14 | Mechanism remains replaceable | Capability identity depends on the current model, workflow or provider |
| L15 | Heartime stays body-free | A profile, candidate or proposal body is persisted in a Beat summary |
| L16 | The protocol is digital | Correctness depends on an FPGA, ASIC or other physical hardware target |
| L17 | Substrate order is canonical | Policy skips, reorders, duplicates or invents a substrate rung |
| L18 | Substrate cognition is truthful | Inference is below 100%, configuration does not reduce cognition, or fixed is above 0% |
| L19 | Fixed means fixed | A fixed candidate or assessment retains runtime cognition inside the admitted work class |
| L20 | Work evidence is exact | A profile from another capability revision or work class is accepted |
| L21 | Equivalence is exact | Assessment names another candidate revision, profile or equivalence contract |
| L22 | Evidence respects time | Assessment predates the candidate or the profile window it claims to evaluate |
| L23 | Savings are finite | Zero baseline cost produces fabricated or infinite savings |
| L24 | Obligation and observation differ | A new evidence window duplicates construction, or cannot create its own evidence record |
| L25 | Policy revision matters | A changed learning-policy revision resolves to the previous obligation identity |
| L26 | Draft is not shadow | A draft candidate enters equivalence evaluation before construction is ready |
| L27 | Evaluation may continue | Non-final independent evidence is treated as either promotion or reconstruction |
| L28 | Contradiction repairs construction | A contradicted candidate remains on the same candidate path |
| L29 | Process cannot substitute | Process returns a different policy or implementation revision and it is accepted |
| L30 | State dimensions stay separate | Candidate status, occupancy status, substrate and epistemic state are collapsed into one lifecycle field |
